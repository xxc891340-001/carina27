# HelloTenant Area Compare Tool — Phase 1 Entity Model

This document defines the Phase 1 data model for the HelloTenant Area Compare Tool, which matches rental areas to a destination (university, postcode, landmark, or city area) using scored, versioned snapshots. The architecture is hybrid: popular destinations are pre-generated by an admin pipeline for SEO performance, while unknown destinations are resolved on-demand and promoted to the pre-generated library if demand warrants it.

---

## Entities

### Destination

The anchor point a user searches from. Geocoded once at creation; slug is canonical and never recomputed.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `slug` | string | Unique. Written once at creation time — never recomputed. Canonical URL segment. |
| `canonical_name` | string | Human-readable display name |
| `type` | enum | `university` \| `postcode` \| `landmark` \| `city_area` |
| `lat` | decimal | Geocoded at creation. Never updated. |
| `lng` | decimal | Geocoded at creation. Never updated. |
| `status` | enum | `pre_generated` \| `on_demand` \| `promoted` |
| `search_count` | integer | Incremented on each on-demand search hit. Used to evaluate promotion eligibility. |
| `last_searched_at` | timestamp | Nullable. Updated on each on-demand search hit. |
| `created_at` | timestamp | |
| `updated_at` | timestamp | |

### AreaSnapshot

An immutable point-in-time capture of scored data for one Area. Every data refresh creates a new row — existing rows are never mutated. Recommendations reference a specific snapshot so results are always reproducible.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `area_id` | uuid FK → Area | The area this snapshot belongs to |
| `source` | enum | `admin_pipeline` \| `on_demand` \| `promoted` |
| `status` | enum | `draft` \| `live` \| `archived`. Only one snapshot per area should be `live` at any time. |
| `snapshot_date` | date | The effective date of the captured data |
| `crime_index` | decimal | Nullable. Lower is better (normalised scale). |
| `transit_score` | decimal | Nullable. Higher is better. |
| `amenity_count` | integer | Nullable. Count of relevant amenities within a defined radius. |
| `rent_estimate_pcm` | integer | Nullable. Estimated monthly rent in pence (or local minor unit). |
| `green_space_score` | decimal | Nullable. Higher is better. |
| `noise_index` | decimal | Nullable. Lower is better. |
| `raw_data` | jsonb | Full source payload retained for auditability and reprocessing. |
| `created_at` | timestamp | |

### InterpretationRule

A versioned ruleset that governs how snapshot scores are turned into Recommendation text. Only one rule should be `is_active = true` at a time in production; historical rules are retained so older Recommendations remain explainable.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `version` | integer | Monotonically increasing. |
| `label` | string | Human-readable identifier (e.g. `"v3-student-neutral"`) |
| `prompt_template` | text | Template passed to the generation layer with score placeholders |
| `summary_structure` | jsonb | Schema/outline the generated summary must conform to |
| `comparison_logic` | jsonb | Weights and thresholds used when ranking areas head-to-head |
| `audience_guidance` | text | Nullable. Notes for prompt tuning per audience segment. |
| `is_active` | boolean | Exactly one rule is active at any time for new Recommendation generation |
| `created_at` | timestamp | |

### Recommendation

The output record linking an Area to a Destination under a specific snapshot and interpretation rule. One record per `(area_id, destination_id)` pair in Phase 1; `renter_profile_id` is null for the shared public interpretation.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `destination_id` | uuid FK → Destination | |
| `area_id` | uuid FK → Area | |
| `area_snapshot_id` | uuid FK → AreaSnapshot | Pins the exact data version used. Immutable after generation. |
| `interpretation_rule_id` | uuid FK → InterpretationRule | Pins the rule version used. Immutable after generation. |
| `renter_profile_id` | uuid FK → RenterProfile | Nullable. `NULL` = shared public recommendation (Phase 1). |
| `walk_bucket` | boolean | `true` if the area centroid is within 30-minute walk of the destination |
| `transit_bucket` | boolean | `true` if the area centroid is within 60-minute transit of the destination |
| `rank_in_bucket` | integer | 1–3. Rank within whichever bucket(s) this area qualifies for |
| `summary` | text | Generated narrative summary |
| `trade_offs` | text | Generated trade-off analysis |
| `practical_guidance` | text | Generated actionable advice |
| `generated_at` | timestamp | When the Recommendation was created |
| `status` | enum | `draft` \| `live` \| `archived` |

## Data Paths

### Pre-generated path (SEO library)

Entities touched: **Destination** (`status = pre_generated`) → **Area** (spatial query selects candidates) → **AreaSnapshot** (`source = admin_pipeline`, `status = live`) → **InterpretationRule** (active rule) → **Recommendation** (`status = live`)

The admin pipeline runs on a schedule. It selects all `pre_generated` Destinations, runs a spatial query to identify candidate Areas within both buckets, fetches/scores data into new AreaSnapshot rows, generates Recommendations, and publishes them. Pages are cached from these records at build time.

---

### On-demand path (user search)

Entities touched: **Destination** (created or looked up; `status = on_demand`) → **Area** (spatial query) → **AreaSnapshot** (`source = on_demand`, initially `status = draft` → `live` on success) → **InterpretationRule** (active rule) → **Recommendation** (`status = live`)

Triggered by a user searching an unknown destination. A Destination row is created if not found. Snapshot and Recommendation are generated synchronously (or near-synchronously). The result is cached. `search_count` is incremented and `last_searched_at` is updated on the Destination row for promotion evaluation.

---

### Promotion path

Entities touched: **Destination** (status updated `on_demand` → `promoted`) → existing **AreaSnapshot** rows (`source` updated to `promoted`) → existing **Recommendation** rows (absorbed into the pre-generated library)

When a Destination's `search_count` crosses the configured threshold, the promotion job re-tags the Destination and its live snapshots/recommendations. From this point forward the pre-generated pipeline owns refresh cycles for this Destination. No new snapshot or recommendation rows are created by the promotion step itself.

---

## Key Invariants

The following rules must be enforced in application code, database constraints, or both.

- **Slug immutability.** `Destination.slug` and `Area.slug` are written once at creation and never updated. Redirects and aliases are handled exclusively via `DestinationAlias`. Code that geocodes or normalises a destination must not overwrite the slug column on an existing row.

- **Snapshot immutability.** Once an `AreaSnapshot` row is created, its scored fields and `raw_data` must not be mutated. Data corrections require a new snapshot row. Application-layer updates must be rejected; consider a database trigger or ORM-level guard.

- **Single live snapshot per area.** At most one `AreaSnapshot` per `area_id` may have `status = live` at any time. Promoting a new snapshot to `live` must atomically archive the previous live snapshot in the same transaction.

- **Recommendation pinning.** The `area_snapshot_id` and `interpretation_rule_id` columns on `Recommendation` are immutable after the row is created. Regenerating a recommendation requires a new `Recommendation` row (with the old row archived), not an update to the existing one.

- **Bucket membership.** An area must satisfy at least one of `walk_bucket = true` or `transit_bucket = true` to appear as a Recommendation. `rank_in_bucket` must be between 1 and 3 inclusive. The combination `(destination_id, area_id, walk_bucket, transit_bucket, rank_in_bucket)` should be unique among `live` recommendations to prevent duplicate rankings.

- **Phase 1 profile constraint.** While `RenterProfile` rows may exist, no business logic reads them in Phase 1. All Phase 1 Recommendations must have `renter_profile_id = NULL`. Inserting a Recommendation with a non-null `renter_profile_id` in Phase 1 is an application error.

- **InterpretationRule uniqueness.** Exactly one `InterpretationRule` row has `is_active = true` at any point in time. Activating a new rule must deactivate the previous one in a single transaction. Existing Recommendations that reference an older rule remain valid and must not be regenerated automatically.
