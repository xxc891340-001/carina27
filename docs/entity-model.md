# HelloTenant Area Compare Tool — Phase 1 Entity Model

This document defines the Phase 1 data model for the HelloTenant Area Compare Tool, which matches rental areas to a destination (university, postcode, landmark, or city area) using scored, versioned snapshots. The architecture is hybrid: popular destinations are pre-generated by an admin pipeline for SEO performance, while unknown destinations are resolved on-demand and promoted to the pre-generated library if demand warrants it.

The platform is bilingual (English and Chinese). Localisation happens at generation time: each locale has its own `InterpretationRule` with its own prompt template and audience assumptions. Chinese content is not a translation of English content — it is generated independently to suit readers who may be unfamiliar with UK housing systems.

HelloTenant is a rule-driven interpretation platform, not an editorial CMS. `InterpretationRule` is the primary knowledge asset. Quality improves through rule evolution, which propagates automatically to all AI-generated content. Human editing of individual Recommendations is the exception — the editorial model is kept deliberately lightweight to reflect this.

## Entities

### AreaSnapshot

An immutable point-in-time capture of scored data for one Area. Every data refresh creates a new row — existing rows are never mutated. Recommendations reference a specific snapshot so results are always reproducible. Snapshots are locale-agnostic: the same snapshot is used when generating both English and Chinese Recommendations.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `area_id` | uuid FK → Area | The area this snapshot belongs to |
| `source` | enum | `admin_pipeline` \| `on_demand` \| `promoted` |
| `status` | enum | `draft` \| `live` \| `archived`. Only one snapshot per area should be `live` at any time. |
| `snapshot_date` | date | The effective date of the captured data |
| `crime_index` | decimal | Nullable. Lower is better (normalised scale). |
| `transit_score` | decimal | Nullable. Higher is better. |
| `amenity_count` | integer | Nullable. Count of relevant amenities within a defined radius. |
| `rent_estimate_pcm` | integer | Nullable. Estimated monthly rent in pence (or local minor unit). |
| `green_space_score` | decimal | Nullable. Higher is better. |
| `noise_index` | decimal | Nullable. Lower is better. |
| `raw_data` | jsonb | Full source payload retained for auditability and reprocessing. |
| `created_at` | timestamp | |

### InterpretationRule

A versioned, locale-specific ruleset that governs how snapshot data is interpreted into Recommendation content. Rules are locale-specific: an `en` rule and a `zh` rule may share a version number but have different prompt templates, audience assumptions, and explanatory depth. Exactly one rule per locale may be `is_active = true` at any time.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `locale` | enum | `en` \| `zh`. Rules are locale-specific and are never shared across locales. |
| `version` | integer | Monotonically increasing within a locale. |
| `label` | string | Human-readable identifier (e.g. `"v3-en-general"`, `"v3-zh-newcomer"`) |
| `prompt_template` | text | Template passed to the AI generation layer. For `zh` rules, instructs the AI to explain UK-specific concepts (GP registration, Council Tax, deposit protection, referencing, guarantors, utility bills) as part of the generated content. |
| `summary_structure` | jsonb | Schema the generated summary must conform to |
| `comparison_logic` | jsonb | Logic used when ranking areas head-to-head |
| `audience_guidance` | text | Nullable. Describes the assumed reader: their familiarity with UK systems, what concepts need explaining, and what tone to use. For `zh` rules this field carries the primary localisation intent. |
| `is_active` | boolean | Exactly one rule per locale is active at any time for new Recommendation generation. |
| `created_at` | timestamp | |

### Recommendation

The output record linking an Area to a Destination under a specific snapshot, interpretation rule, and locale. Phase 1 produces two Recommendation rows per `(area_id, destination_id)` pair — one per locale — both generated from the same `AreaSnapshot` but from locale-specific `InterpretationRule` records. Content fields are generated independently per locale and are not translations of each other.

| Field | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key |
| `locale` | enum | `en` \| `zh`. The locale this content was generated for. |
| `destination_id` | uuid FK → Destination | |
| `area_id` | uuid FK → Area | |
| `area_snapshot_id` | uuid FK → AreaSnapshot | Pins the exact data version used. Immutable after generation. Same snapshot is referenced by both locale rows. |
| `interpretation_rule_id` | uuid FK → InterpretationRule | Pins the locale-specific rule version used. Immutable after generation. |
| `renter_profile_id` | uuid FK → RenterProfile | Nullable. `NULL` = shared public recommendation (Phase 1). |
| `walk_bucket` | boolean | `true` if the area centroid is within 30-minute walk of the destination |
| `transit_bucket` | boolean | `true` if the area centroid is within 60-minute transit of the destination |
| `rank_in_bucket` | integer | 1–3. Rank within whichever bucket(s) this area qualifies for |
| `summary` | text | Generated narrative summary in the Recommendation's locale |
| `trade_offs` | text | Generated trade-off analysis in the Recommendation's locale |
| `practical_guidance` | text | Generated awareness guidance — things to notice or investigate ("what to look out for"). In `zh` this layer may include explanation of UK-specific concepts before the awareness points. |
| `next_actions` | text | Generated action guidance — concrete, time-bound tasks for the renter ("what to do next"). In `zh` this layer is localised, not translated: actions are written with the assumption that the reader is new to UK systems. |
| `edit_origin` | enum | `ai_generated` \| `human_edited`. `ai_generated` rows regenerate automatically on rule or data updates. `human_edited` rows route to a lightweight manual approval step before the new AI content goes live. |
| `review_status` | enum | `pending` \| `approved` \| `rejected`. Lightweight approval gate. Most AI-generated content is auto-approved by the GenerationJob; human-edited rows require a manual approval. |
| `regeneration_trigger` | enum | Nullable. `data_refresh` \| `rule_update` \| `manual`. Set on rows created by a regeneration job to record why regeneration occurred. Null on original first-generation rows. |
| `generated_at` | timestamp | When the Recommendation was created |
| `status` | enum | `draft` \| `live` \| `archived` |

## Data Paths

### Pre-generated path (SEO library)

Entities touched: **Destination** (`status = pre_generated`) → **Area** (spatial query selects candidates) → **AreaSnapshot** (`source = admin_pipeline`, `status = live`) → **InterpretationRule** (active rule, per locale) → **Recommendation** (`status = live`, one row per locale)

The admin pipeline runs on a schedule. It selects all `pre_generated` Destinations, runs a spatial query to identify candidate Areas within both buckets, fetches and scores data into new AreaSnapshot rows, then runs two GenerationJobs (one `en`, one `zh`) to produce Recommendations. Pages are cached from these records at build time.

---

### On-demand path (user search)

Entities touched: **Destination** (created or looked up; `status = on_demand`) → **Area** (spatial query) → **AreaSnapshot** (`source = on_demand`, `status = draft` → `live` on success) → **InterpretationRule** (active rule for the user's locale) → **Recommendation** (`status = live`, for the user's locale)

Triggered by a user searching an unknown destination. A Destination row is created if not found. The AreaSnapshot is created once and shared across locales. A Recommendation is generated for the requesting user's locale immediately; the other locale is generated asynchronously. `search_count` is incremented and `last_searched_at` is updated on the Destination row for promotion evaluation.

---

### Promotion path

Entities touched: **Destination** (status updated `on_demand` → `promoted`) → existing **AreaSnapshot** rows (`source` updated to `promoted`) → existing **Recommendation** rows (absorbed into the pre-generated library)

When a Destination's `search_count` crosses the configured threshold, the promotion job re-tags the Destination and its live snapshots and recommendations across all locales. From this point forward the pre-generated pipeline owns refresh cycles for this Destination. No new snapshot or recommendation rows are created by the promotion step itself.

## Key Invariants

The following rules must be enforced in application code, database constraints, or both.

- **Slug immutability.** `Destination.slug` and `Area.slug` are written once at creation and never updated. Redirects and aliases are handled exclusively via `DestinationAlias`. Code that geocodes or normalises a destination must not overwrite the slug column on an existing row.

- **Snapshot immutability.** Once an `AreaSnapshot` row is created, its scored fields and `raw_data` must not be mutated. Data corrections require a new snapshot row. Application-layer updates must be rejected; consider a database trigger or ORM-level guard.

- **Snapshot locale-agnosticism.** A single `AreaSnapshot` row is shared by all locale-specific Recommendations for the same area. Snapshots must never be duplicated per locale. If an `en` and `zh` Recommendation exist for the same `(area_id, destination_id)` pair, they must reference the same `area_snapshot_id`.

- **Single live snapshot per area.** At most one `AreaSnapshot` per `area_id` may have `status = live` at any time. Promoting a new snapshot to `live` must atomically archive the previous live snapshot in the same transaction.

- **Recommendation pinning.** The `area_snapshot_id` and `interpretation_rule_id` columns on `Recommendation` are immutable after the row is created. Regenerating a recommendation requires a new `Recommendation` row (with the old row archived), not an update to the existing one. All generated content fields (`summary`, `trade_offs`, `practical_guidance`, `next_actions`) are immutable after generation — corrections require a new row.

- **Live recommendation uniqueness per locale.** At most one `Recommendation` per `(area_id, destination_id, locale)` may have `status = live` at any time. `walk_bucket`, `transit_bucket`, and `rank_in_bucket` are locale-agnostic structural values and must be consistent across the `en` and `zh` rows for the same `(area_id, destination_id)` pair.

- **Bucket membership.** An area must satisfy at least one of `walk_bucket = true` or `transit_bucket = true` to appear as a Recommendation. `rank_in_bucket` must be between 1 and 3 inclusive.

- **Phase 1 profile constraint.** While `RenterProfile` rows may exist, no business logic reads them in Phase 1. All Phase 1 Recommendations must have `renter_profile_id = NULL`. Inserting a Recommendation with a non-null `renter_profile_id` in Phase 1 is an application error.

- **InterpretationRule uniqueness per locale.** Exactly one `InterpretationRule` row per locale has `is_active = true` at any point in time. Activating a new rule for a locale must deactivate the previous rule for that locale in a single transaction. Rules for different locales are activated independently. Existing Recommendations that reference an older rule remain valid and are not regenerated automatically — regeneration is a deliberate operation, not an automatic consequence of rule activation.

- **Regeneration and edit_origin.** When a GenerationJob creates a new draft Recommendation that would replace a live row with `edit_origin = human_edited`, the new draft must be set to `review_status = pending` regardless of the job's auto-approval setting. A human must approve the new AI content before it goes live. Rows with `edit_origin = ai_generated` may be auto-approved by the job.

- **GenerationJob locale consistency.** A `GenerationJob` must reference an `InterpretationRule` with the same `locale` as the job itself. A job with `locale = zh` must not reference an `en` InterpretationRule.
